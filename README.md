# Автоматическая сборка видео из кадров

Локальное приложение для Windows собирает длинный MP4-ролик из изображений и одного файла с озвучкой. Время окончания каждого кадра берётся из начала имени изображения, начало вычисляется автоматически. Никаких внешних API, облачных сервисов или подписок не требуется.

## Как работает временная метка

Метка означает **время окончания текущего кадра**, а не его длительность. Первый кадр начинается в `00:00:00.000`, следующий — в момент окончания предыдущего.

Например:

```text
[0-05]_scene1.jpg  -> 00:00:00–00:00:05, длительность 5 секунд
[0-14]_scene2.jpg  -> 00:00:05–00:00:14, длительность 9 секунд
[0-21]_scene3.jpg  -> 00:00:14–00:00:21, длительность 7 секунд
[1-02]_scene4.jpg  -> 00:00:21–00:01:02, длительность 41 секунда
```

Поддерживаются форматы:

```text
[MM-SS]_название.jpg
[MM-SS.mmm]_название.jpg
[HH-MM-SS]_название.jpg
[HH-MM-SS.mmm]_название.jpg
```

Корректные примеры: `[0-05]_кадр.jpg`, `[1-02.250]_scene.png`, `[12-30]_frame.webp`, `[01-02-15.750]_финал.jpeg`. Секунды должны быть от `00` до `59`; в часовом формате минуты также должны быть от `00` до `59`. После `]` разрешены пробелы, кириллица, латиница, дефисы, подчёркивания, цифры и дополнительные точки.

Изображения: PNG, JPG, JPEG, WEBP, BMP. Аудио: MP3, WAV, M4A, AAC, OGG, FLAC.

## Требования

- Windows 10 или 11;
- Python 3.11 или новее;
- FFmpeg и ffprobe в `PATH` либо явные пути к `ffmpeg.exe` и `ffprobe.exe` в интерфейсе;
- свободное место для промежуточных клипов. Для длинного ролика желательно иметь несколько гигабайт.

Ограничения одного проекта: до 1000 изображений, до 100 МБ на одно изображение, до 2 ГБ изображений суммарно и один аудиофайл до 200 МБ. Эти лимиты защищают RAM и диск от случайного переполнения.

Проверка установленных программ в PowerShell или CMD:

```powershell
python --version
ffmpeg -version
ffprobe -version
```

## Установка Python в Windows

1. Скачайте актуальный Python 3.11+ с [python.org](https://www.python.org/downloads/windows/).
2. В установщике включите **Add python.exe to PATH**.
3. Завершите установку и откройте новое окно терминала.
4. Выполните `python --version`.

Если команда `python` открывает Microsoft Store, отключите псевдонимы Python в «Параметры → Приложения → Дополнительные параметры приложений → Псевдонимы выполнения приложений» либо используйте команду `py` вместо `python`.

## Установка FFmpeg в Windows

Самый простой вариант при наличии Windows Package Manager:

```powershell
winget install --id Gyan.FFmpeg -e
```

Затем закройте терминал, откройте его снова и проверьте `ffmpeg -version` и `ffprobe -version`.

Ручной вариант:

1. Откройте страницу [FFmpeg Download](https://ffmpeg.org/download.html#build-windows) и скачайте готовую Windows-сборку.
2. Распакуйте архив, например в `C:\Tools\ffmpeg`.
3. Добавьте папку `C:\Tools\ffmpeg\bin` в пользовательскую переменную `PATH`.
4. Откройте новый терминал и выполните команды проверки.

Если изменять `PATH` не хочется, укажите полные пути к обоим EXE в боковой панели приложения.

## Установка приложения

Откройте PowerShell или CMD в папке проекта. Создайте виртуальное окружение:

```powershell
python -m venv .venv
```

Активация в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скрипта, один раз для текущего пользователя выполните:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Активация в CMD:

```bat
.venv\Scripts\activate.bat
```

Установите зависимости:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Запуск

Из корня проекта с активным окружением:

```powershell
streamlit run app.py
```

Надёжный вариант, если команда `streamlit` не попала в `PATH`:

```powershell
python -m streamlit run app.py
```

После первичной установки приложение также можно запускать двойным щелчком по `start_app.bat`.

Браузер обычно открывается автоматически. Если нет, перейдите по локальному адресу, который покажет Streamlit, обычно `http://localhost:8501`.

## Использование

1. Загрузите изображения в произвольном порядке или укажите локальную папку. Приложение сортирует кадры по числовому времени, не по имени.
2. Загрузите один файл с полной озвучкой.
3. Исправьте все красные ошибки. Повреждённые изображения проверяются Pillow, аудио — ffprobe.
4. Проверьте отсортированную таблицу. В поле «Окончание» можно ввести `HH:MM:SS.mmm`; исходный файл переименовывать не нужно. Можно отметить отдельный кадр для удаления.
5. Выберите разрешение, FPS, способ вписывания, движение, переход и параметры аудио.
6. Выберите, что делать при несовпадении конца таймлайна и аудио.
7. Создайте 15- или 30-секундный предпросмотр либо задайте свой диапазон.
8. Нажмите «Собрать финальное видео». Во время работы показываются этап, обработанный кадр и последние действия. Кнопка отмены завершает активный FFmpeg и очищает промежуточные файлы.
9. После проверки ffprobe ролик можно воспроизвести, скачать или открыть его папку.

До запуска приложение оценивает необходимое свободное место, включая резерв 512 МБ. Если места недостаточно, кнопка рендера блокируется.

Переход `Crossfade (синхробезопасный fade)` намеренно не перекрывает клипы: затухание выполняется внутри времени кадра. Это сохраняет точные смысловые отметки и общую длительность. Синхронизация имеет приоритет перед эффектом.

## Где находится видео

Каждый запуск получает уникальный ID, поэтому проекты не смешиваются. Архивная копия финального файла находится здесь:

```text
output/<ID-проекта>/final_video.mp4
```

Последний успешно собранный финальный ролик также атомарно копируется в требуемый простой путь `output/final_video.mp4`. Предпросмотр: `output/<ID-проекта>/preview.mp4`. Итоговый контейнер — MP4, видео — H.264 (`libx264`, `yuv420p`), звук — AAC, частота кадров постоянная.

Промежуточные материалы находятся в `temp/<ID-проекта>`, журналы FFmpeg — в `logs/<ID-проекта>/ffmpeg.log`. При успешном рендеринге промежуточные файлы удаляются, если не включён режим отладки.

## Распространённые ошибки

### FFmpeg или ffprobe не найден

Откройте новое окно терминала после установки. Проверьте обе команды. Либо вставьте полные пути к EXE в боковой панели приложения.

### Неправильное количество секунд

`[1-75]_scene.jpg` неверно: секунды могут быть только `00–59`. Для 1 минуты 15 секунд используйте `[1-15]_scene.jpg`.

### Одинаковое время окончания

Два кадра с одной отметкой получили бы нулевую длительность. Измените метку через таблицу или переименуйте один файл.

### Изображение не открывается

Откройте его в графическом редакторе и пересохраните в PNG/JPEG. Расширение файла само по себе не гарантирует, что содержимое корректно.

### Нет прав записи или закончилось место

Переместите проект в обычную пользовательскую папку, например `Документы`, и освободите место. Не запускайте проект из защищённой системной папки.

### FFmpeg завершился с ошибкой

В интерфейсе раскройте последние строки журнала. Полный журнал находится в `logs/<ID-проекта>/ffmpeg.log`. Пути передаются FFmpeg отдельными аргументами, поэтому пробелы и кириллица поддерживаются.

### Очень короткий кадр пропущен

При выбранном FPS кадр должен занимать хотя бы один физический видеокадр. Увеличьте его интервал или выберите более высокий FPS.

## Тесты

С активным виртуальным окружением выполните из корня проекта:

```powershell
pytest
```

Тесты проверяют допустимые и ошибочные метки, миллисекунды, числовую сортировку, построение непрерывного таймлайна, дубликаты, ручные изменения и варианты завершения ролика.

Если FFmpeg/ffprobe доступны, обычная команда `pytest` также выполняет настоящий интеграционный рендер, проверяет MP4 и извлекает кадры после смысловых границ. Только быстрые unit-тесты без рендера:

```powershell
pytest -m "not integration"
```

Дополнительная проверка синтаксиса всех модулей:

```powershell
python -m compileall -q .
```

## Очистка временных файлов

Закройте приложение и удалите содержимое папки `temp`, но оставьте саму папку. В PowerShell из корня проекта:

```powershell
Get-ChildItem -LiteralPath .\temp -Force | Remove-Item -Recurse -Force
```

Это удаляет только промежуточные данные. Готовые ролики остаются в `output`. Старые результаты и логи при необходимости можно удалить вручную из `output` и `logs` после закрытия приложения.

## Безопасное закрытие

Если идёт рендер, сначала нажмите «Отменить рендеринг» и дождитесь итогового статуса. Затем в терминале нажмите `Ctrl+C`. Не удаляйте `temp` и не завершайте FFmpeg через Диспетчер задач во время штатной отмены.

Загруженные имена никогда не используются как пути для записи: приложение создаёт внутренние безопасные имена и отдельный каталог для каждой сессии. Команды FFmpeg запускаются списком аргументов без `shell=True`. Подробный stderr остаётся только в локальном журнале и не выводится пользователю как необработанная ошибка.

## Известные ограничения

- Настоящий перекрывающий crossfade заменён синхробезопасным fade внутри границ кадра: точные временные отметки важнее эффекта.
- Очень короткий интервал, не занимающий ни одного физического кадра при выбранном FPS, нужно увеличить вручную.
- Одновременно в одной сессии выполняется один рендер.
- Для сотен кадров требуется заметное свободное место: приложение создаёт отдельные H.264-клипы, чтобы не превышать лимит командной строки Windows.
- Streamlit работает локально в браузере; закрытие вкладки не является штатной отменой запущенного процесса — используйте кнопку отмены.

Дополнительные короткие инструкции находятся в [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Архитектура

- `app.py` — интерфейс и состояние Streamlit;
- `models/` — типизированные модели таймлайна и настроек;
- `services/filename_parser.py`, `timeline_builder.py`, `timeline_validator.py` — чистая логика временных меток;
- `services/image_processor.py` — EXIF, масштабирование и фон через Pillow;
- `services/video_renderer.py`, `ffmpeg_builder.py` — масштабируемый по клипам FFmpeg-пайплайн;
- `services/media_probe.py` — проверка аудио и результата;
- `services/workspace_manager.py` — изоляция и очистка проектов;
- `tests/` — unit-тесты.
