# AutoFrames

AutoFrames автоматически собирает длинное видео из изображений и одной или нескольких частей озвучки. Если аудио разделено, дорожки склеиваются строго в выбранном порядке: вторая начинается после окончания первой, без наложения. Границы сцен подстраиваются под окончания предложений, фраз и естественные паузы в речи. Имена изображений ни на что не влияют: кадры идут строго в порядке добавления. Итоговый MP4 создаётся через FFmpeg в формате H.264/AAC.

Проект разделён на три независимые части:

- `frontend/` — Next.js 16, TypeScript и App Router; размещается на Vercel;
- `backend/` — FastAPI, Pillow, ffprobe и FFmpeg; размещается отдельным Docker-сервисом на Railway или Render;
- `legacy_streamlit/` — прежняя полностью локальная Streamlit-версия как резервный вариант.

FFmpeg-рендер никогда не запускается внутри Vercel Functions. Браузер отправляет файлы напрямую в FastAPI, получает состояние задачи по API и скачивает готовый MP4 с backend-сервера.

## Автоматическая синхронизация по аудио

Можно выбрать сразу несколько аудиофайлов и изменить их порядок в очереди перед загрузкой. Backend проверяет каждую часть, последовательно объединяет их в одну нормализованную AAC-дорожку и только после этого анализирует речь и строит общий таймлайн. Между файлами не добавляется искусственная пауза: сохраняются только тишина и паузы, уже записанные в самих исходниках.

После анализа доступно три логики смены кадров:

- **Адаптивно** — режим по умолчанию; совместно учитывает количество фотографий, длительность аудио, объём речи, предложения, фразы и качество пауз;
- **По смыслу и паузам** — сильнее предпочитает окончания предложений и фраз, даже если сцены получаются менее равномерными;
- **Ровный темп** — стремится к одинаковой длительности сцен, но при наличии временных меток слов всё равно не ставит границу внутри произносимого слова.

Если фотографий больше, чем смысловых окончаний, дополнительные смены ставятся только в безопасных внутренних промежутках речи. Начальная и хвостовая тишина не заполняются искусственными переходами.

Можно использовать любые имена изображений, включая одинаковые имена и строки в квадратных скобках. Имя остаётся только подписью в интерфейсе и не используется для сортировки или определения длительности сцены.

Локальный анализ FFmpeg всегда находит участки тишины. AutoFrames глобально выбирает лучший набор границ для всех кадров сразу, игнорирует начальную и конечную тишину и гарантирует, что последний кадр заканчивается точно вместе с аудио. Если пауз недостаточно, используется равномерное распределение с понятным предупреждением в интерфейсе.

Для максимальной точности можно включить серверное распознавание речи. Backend создаёт временную mono MP3-копию, получает временные метки слов и фраз через модель `whisper-1`, совмещает их с локальными паузами и ставит смены в конце предложений. Граница допускается только в безопасном промежутке между словами с запасом на округление к 24/25/30/60 FPS. Последнее окончание речи не превращается в переход на хвостовой тишине.

Облачный режим выключен по умолчанию. Если ключ не настроен, достигнут локальный лимит, сервис распознавания недоступен или подготовленный файл больше 24 МиБ, проект автоматически продолжает работу по локальным паузам. Если распознавание уже получено, но безопасных межсловных границ физически меньше, чем кадров, таймлайн помечается некорректным: система не режет слово ради заполнения всех сцен.

Для включения высокоточного режима на backend:

```dotenv
OPENAI_TRANSCRIPTION_ENABLED=true
OPENAI_API_KEY=sk-...
OPENAI_TRANSCRIPTION_LANGUAGE=ru
```

Ключ остаётся только на backend и никогда не должен иметь префикс `NEXT_PUBLIC_`. Запрос использует официальный endpoint [Audio Transcriptions](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create). Согласно актуальным [правилам обработки API-данных](https://developers.openai.com/api/docs/guides/your-data#default-usage-policies-by-endpoint), данные API не используются для обучения без явного opt-in, но содержимое может попадать в abuse-monitoring logs со сроком хранения до 30 дней по умолчанию. Перед включением для голосов сотрудников проверьте договорные условия, доступность ZDR/MAM и внутреннюю политику согласия.

## Возможности web-версии

- множественная загрузка PNG, JPG, JPEG, WEBP и BMP;
- загрузка одной или нескольких частей MP3, WAV, M4A, AAC, OGG или FLAC с управлением порядком воспроизведения;
- проверка MIME-типа, расширения и содержимого файлов;
- автоматическая синхронизация сцен по предложениям, фразам и паузам в речи;
- порядок кадров строго по добавлению, независимо от имён;
- удаление отдельного кадра до рендеринга;
- форматы 16:9, 9:16, 1:1 и пользовательский чётный размер;
- 24, 25, 30 или 60 FPS;
- обрезка, размытый фон или цветной фон;
- Ken Burns, умное движение по формату фотографии, fade и безопасный fade-вариант перехода без смещения таймлайна; умный режим отключает движение на слишком коротких сценах и выбирает горизонтальную/вертикальную панораму либо мягкий zoom по геометрии исходника;
- настройки громкости, нормализации и аудиозатухания;
- фоновый рендеринг, polling прогресса и безопасная отмена FFmpeg;
- финальная проверка кодеков, FPS, размера и длительности;
- скачивание готового MP4.

## API backend

После запуска интерактивная документация доступна по адресам:

- Swagger UI: `http://localhost:8000/docs`;
- ReDoc: `http://localhost:8000/redoc`;
- health-check: `GET http://localhost:8000/health`.

Основные маршруты:

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/api/projects` | создать проект |
| `POST` | `/api/projects/{id}/images` | загрузить изображения |
| `POST` | `/api/projects/{id}/audio` | загрузить одну дорожку (`file`) или последовательную очередь (`files`) |
| `GET` | `/api/projects/{id}/timeline` | построить и проверить таймлайн |
| `POST` | `/api/projects/{id}/sync-strategy` | перестроить автотаймлайн (`adaptive`, `semantic`, `even`) |
| `POST` | `/api/projects/{id}/render` | запустить рендеринг |
| `GET` | `/api/projects/{id}/status` | состояние, прогресс и журнал |
| `GET` | `/api/projects/{id}/progress` | компактный прогресс |
| `POST` | `/api/projects/{id}/cancel` | отменить задачу |
| `GET` | `/api/projects/{id}/result` | скачать MP4 |
| `DELETE` | `/api/projects/{id}` | удалить проект и его файлы |

Ошибки API имеют единый безопасный формат:

```json
{
  "error": {
    "code": "unsupported_image_type",
    "message": "Понятное описание ошибки",
    "details": {}
  }
}
```

Абсолютные серверные пути клиенту не возвращаются.

## Быстрый локальный запуск через Docker Compose

Требуется Docker Desktop с Compose v2.

```powershell
git clone https://github.com/NotchKhan/AutoFrames.git
cd AutoFrames
docker compose up --build
```

Compose работает локально без облачного ключа. Для высокоточного режима сначала создайте корневой `.env` (`Copy-Item backend/.env.example .env`), затем включите распознавание и добавьте ключ в этот файл.

Откройте:

- frontend: `http://localhost:3000`;
- backend API: `http://localhost:8000/docs`.

Остановка:

```powershell
docker compose down
```

Удаление контейнеров вместе с локальным томом проектов:

```powershell
docker compose down --volumes
```

## Локальная разработка без Docker

### Backend

Требуются Python 3.11 или новее, FFmpeg и ffprobe в `PATH`.

Проверка:

```powershell
python --version
ffmpeg -version
ffprobe -version
```

Создание окружения и запуск в PowerShell:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
python entrypoint.py
```

Файл `backend/.env` загружается автоматически. Для полностью локального режима оставьте `OPENAI_TRANSCRIPTION_ENABLED=false`; для высокоточного режима укажите серверный ключ по примеру выше.

Для CMD активация выполняется командой:

```bat
.venv\Scripts\activate.bat
```

### Frontend

Требуется Node.js 20.9 или новее.

```powershell
cd frontend
Copy-Item .env.example .env.local
npm install
npm run dev
```

В `.env.local` для локального запуска должно быть:

```dotenv
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Локально frontend может определить `http://localhost:8000` автоматически. В опубликованной версии автоматического fallback нет: нужен реальный публичный адрес backend.

## Переменные окружения

### Frontend

| Переменная | Обязательно | Пример |
|---|---:|---|
| `NEXT_PUBLIC_API_URL` | да | `https://api.example.com` |

Значение является публичным и встраивается в клиентский JavaScript во время сборки. В нём нельзя хранить секреты. Для облачной сборки адрес должен быть публичным HTTPS URL: `localhost` относится к устройству посетителя, а не к серверу проекта. Vercel-сборка намеренно завершается ошибкой, если адрес отсутствует или указывает на loopback-интерфейс; Dockerfile также требует явный build arg. Только локальный `docker compose` разрешает свой предусмотренный `localhost`.

### Backend

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `FRONTEND_ORIGIN` | `http://localhost:3000` | разрешённый CORS origin; несколько адресов разделяются запятыми |
| `MAX_FILE_SIZE_MB` | `100` | максимум для одного изображения или аудиофайла |
| `MAX_TOTAL_SIZE_MB` | `2048` | общий максимум проекта |
| `MAX_IMAGE_COUNT` | `500` | максимум изображений проекта |
| `MAX_AUDIO_TRACKS` | `20` | максимум последовательных частей озвучки в одной загрузке |
| `PROJECT_TTL_HOURS` | `24` | срок хранения неактивного проекта |
| `STORAGE_RESERVE_MIN_MB` | `256` | минимальный объём свободного места, который рендер никогда не планирует занять; явное значение ниже `128` отклоняется при запуске |
| `STORAGE_RESERVE_MAX_MB` | `512` | верхняя граница динамического защитного резерва |
| `STORAGE_RESERVE_PERCENT` | `10` | доля полной ёмкости filesystem для динамического резерва, от `0` до `50` |
| `OPENAI_TRANSCRIPTION_ENABLED` | `false` | явно включает отправку подготовленного аудио в сервис распознавания |
| `OPENAI_API_KEY` | — | секретный серверный ключ; не передаётся во frontend |
| `OPENAI_API_BASE_URL` | `https://api.openai.com/v1` | HTTPS base URL совместимого transcription API |
| `OPENAI_TRANSCRIPTION_LANGUAGE` | автоопределение | ISO-код языка, например `ru`; пустое значение включает автоопределение |
| `OPENAI_TRANSCRIPTION_TIMEOUT_SECONDS` | `600` | тайм-аут одного запроса распознавания |
| `OPENAI_TRANSCRIPTION_MAX_MINUTES_PER_HOUR` | `120` | локальный почасовой лимит распознаваемого аудио на один backend-процесс |
| `AUDIO_ANALYSIS_CONCURRENCY` | `2` | максимум одновременно анализируемых дорожек и FFmpeg-процессов анализа |
| `RENDER_CONCURRENCY` | `1` | максимум одновременно выполняемых FFmpeg-рендеров; остальные проекты ждут в очереди |
| `AUDIO_MINIMUM_SCENE_MS` | `700` | рекомендуемая минимальная длительность сцены |
| `AUDIO_SILENCE_NOISE_DB` | `-35` | порог тишины для FFmpeg `silencedetect` |
| `AUDIO_MINIMUM_SILENCE_MS` | `280` | минимальная длительность распознаваемой паузы |
| `STORAGE_ROOT` | `backend/data` | постоянный каталог проектов, логов и результатов |
| `FFMPEG_BINARY` | поиск в `PATH` | явный путь к FFmpeg |
| `FFPROBE_BINARY` | поиск в `PATH` | явный путь к ffprobe |
| `PORT` | `8000` | порт backend-контейнера |

Защитный резерв диска вычисляется перед каждым рендером как
`clamp(полная ёмкость filesystem × STORAGE_RESERVE_PERCENT / 100, STORAGE_RESERVE_MIN_MB, STORAGE_RESERVE_MAX_MB)`
и прибавляется к оценке временных кадров, клипов, MP4 и аудио. Поэтому небольшой ролик не блокируется
фиксированным резервом, превышающим весь volume, но backend всё равно отказывается начинать задачу,
если после оценённых записей не останется безопасного минимума. Значения задаются в MiB
(`1 МБ = 1024² байт`). Для Railway используйте явные значения
`256`, `512` и `10`; уменьшить минимум можно не ниже `128` и только после наблюдения за фактическим потреблением.

Готовые примеры находятся в `frontend/.env.example` и `backend/.env.example`. Файлы `.env*`, кроме примеров, не добавляются в Git и исключены из Docker build context. Почасовой лимит хранится в памяти процесса: он не заменяет общий billing limit провайдера, а при нескольких репликах умножается на их количество.

## Размещение frontend на Vercel

1. Откройте Vercel и нажмите **Add New → Project**.
2. Подключите GitHub и выберите репозиторий `NotchKhan/AutoFrames`.
3. В поле **Root Directory** укажите `frontend`.
4. Выберите **Framework Preset: Next.js**.
5. Сначала опубликуйте backend и убедитесь, что `https://BACKEND-DOMAIN/health` возвращает HTTP 200 и JSON со `status: ok`.
6. В **Settings → Environment Variables** добавьте `NEXT_PUBLIC_API_URL` со значением этого публичного HTTPS-адреса без завершающего `/`. Отметьте Production, а если пользуетесь preview deployment — также Preview.
7. Нажмите **Deploy**. Сборка остановится с понятной ошибкой, если переменная отсутствует, некорректна или указывает на `localhost`.
8. Скопируйте стабильный production-домен Vercel и укажите его в `FRONTEND_ORIGIN` backend-сервиса. Нужные preview-домены можно перечислить там же через запятую.
9. После любого изменения API URL выполните **Redeploy** frontend, потому что `NEXT_PUBLIC_*` встраивается во время сборки; простое изменение переменной у уже собранного deployment не меняет его JavaScript.

После подключения репозитория Vercel автоматически создаёт новый deployment при каждом push в отслеживаемую ветку.

### Если frontend сообщает, что backend недоступен

1. Откройте `https://BACKEND-DOMAIN/health` напрямую. Если нет HTTP 200, сначала исправьте или запустите backend deployment.
2. Проверьте, что `NEXT_PUBLIC_API_URL` задан именно для окружения открытого deployment и содержит URL backend, а не frontend.
3. Выполните Redeploy frontend. Переменная времени выполнения не исправляет уже собранный bundle.
4. В backend укажите точный origin открытого frontend в `FRONTEND_ORIGIN` без пути и завершающего `/`; несколько адресов разделяются запятыми.
5. Не используйте HTTP backend с HTTPS frontend — браузер заблокирует такой mixed-content запрос.

## Размещение backend на Railway

1. Создайте в Railway новый проект через **Deploy from GitHub repo**.
2. Выберите тот же репозиторий `NotchKhan/AutoFrames`.
3. В настройках сервиса укажите **Root Directory**: `/backend`, а в **Config File Path** — `/backend/railway.json`. Путь к конфигурации задаётся от корня репозитория и не наследует Root Directory.
4. Подключите постоянный volume и смонтируйте его в `/data`; задайте `STORAGE_ROOT=/data` и `RAILWAY_RUN_UID=0`. Образ по умолчанию работает от пользователя `app`, а Railway монтирует volume с владельцем root, поэтому без этой настройки каталог может оказаться недоступен для записи.
5. Не задавайте `PORT` вручную: Railway передаёт его при запуске, а `entrypoint.py` уже использует значение платформы.
6. Для заявленных лимитов выбирайте как минимум Hobby с volume 5 GB; рекомендуется 10 GB, особенно для проектов до 2 GB и 500 изображений. На Free/Trial volume 0.5 GB используйте ограниченный профиль `MAX_TOTAL_SIZE_MB=128` и `PROJECT_TTL_HOURS=1`. Доступность, названия, цены и лимиты тарифов могут меняться — проверьте их в текущем аккаунте Railway перед публикацией.
7. Добавьте `FRONTEND_ORIGIN`, `MAX_FILE_SIZE_MB`, `MAX_TOTAL_SIZE_MB`, `MAX_IMAGE_COUNT`, `PROJECT_TTL_HOURS`, а также явные настройки дискового резерва: `STORAGE_RESERVE_MIN_MB=256`, `STORAGE_RESERVE_MAX_MB=512`, `STORAGE_RESERVE_PERCENT=10`. Старое имя `MIN_FREE_RESERVE_MB` не используется.
8. Если backend закрыт корпоративным SSO/identity-aware proxy, для высокоточного режима дополнительно задайте секрет `OPENAI_API_KEY` и `OPENAI_TRANSCRIPTION_ENABLED=true`. На публичном API оставьте режим выключенным.
9. Оставьте одну реплику/worker: очереди анализа и рендеринга хранятся в памяти процесса, а проекты — на локальном volume.
10. Сгенерируйте публичный HTTPS-домен backend.
11. Проверьте `https://BACKEND-DOMAIN/health` и `/docs`.
12. Вставьте домен в `NEXT_PUBLIC_API_URL` проекта Vercel и выполните Redeploy.
13. Оставьте Railway auto-deploy включённым — каждый push в подключённую ветку пересоберёт backend.

## Размещение backend на Render

1. Создайте Blueprint из GitHub и при настройке укажите **Blueprint Path**: `backend/render.yaml` — файл находится во вложенном каталоге и не будет найден по стандартному пути в корне.
2. Для ручного **New → Web Service** выберите репозиторий `NotchKhan/AutoFrames`, среду **Docker**, **Root Directory** `backend`, Dockerfile `./backend/Dockerfile` и Docker context `./backend`. Пути Dockerfile и context в Render задаются от корня репозитория.
3. Укажите health-check path `/health`.
4. Для FFmpeg рекомендуется как минимум инстанс Standard с 2 GB RAM. Названия, цены и доступность тарифов могут меняться — проверьте текущие варианты в аккаунте Render.
5. Подключите persistent disk в `/data`, задайте `STORAGE_ROOT=/data` и оставьте одну реплику. Для заявленных лимитов рекомендуется диск 10 GB; его наличие и максимальный размер зависят от тарифа.
6. Добавьте backend-переменные окружения. Облачное распознавание в `render.yaml` намеренно выключено; включайте его вместе с секретом `OPENAI_API_KEY` только после защиты API корпоративным доступом.
7. После успешного deploy получите HTTPS URL backend.
8. Добавьте URL в `NEXT_PUBLIC_API_URL` Vercel и выполните Redeploy frontend.
9. Включите **Auto-Deploy: Yes**. Blueprint создаёт сервис из `backend/render.yaml`, но размер инстанса и persistent disk проверьте и настройте отдельно.

## Безопасность

- исходное имя используется только для отображения и разбора метки, но никогда не используется как путь записи;
- внутренние файлы получают случайные UUID-имена;
- ID проекта строго проверяется как 32-значный hex;
- Pillow проверяет фактический формат и декодируемость каждого изображения;
- ffprobe проверяет аудиопоток и длительность каждой части, а также итоговой объединённой дорожки;
- есть ограничения количества, размера одного файла и общего объёма;
- все subprocess-команды FFmpeg передаются списком аргументов с `shell=False`;
- каждый проект получает отдельные каталоги;
- истёкшие проекты удаляются автоматически;
- CORS разрешён только для `FRONTEND_ORIGIN`;
- секреты и `.env*` исключены из Git и Docker context;
- временная MP3-копия для распознавания удаляется сразу после запроса, а распознанные метки хранятся только в памяти до удаления/истечения проекта;
- исходные медиа хранятся до `DELETE /api/projects/{id}` или TTL неактивности.

ID проекта является случайным идентификатором, но **не авторизацией**, а CORS — только браузерной политикой. Текущий API не содержит учётных записей и прикладного rate limit. Для работы сотрудников и особенно перед включением оплачиваемого распознавания закройте весь backend корпоративным SSO, Cloudflare Access или другим identity-aware reverse proxy. Не публикуйте `OPENAI_API_KEY` во frontend, логах или Docker build args.

## Известные ограничения

- текущая очередь задач хранится в памяти одного backend-процесса; используйте одну реплику/worker;
- лимит расходов на распознавание и семафоры анализа также локальны для процесса; несколько реплик требуют общей очереди и общего счётчика бюджета;
- перезапуск backend отменяет активные рендеры, хотя файлы на persistent volume сохраняются до TTL-очистки;
- для горизонтального масштабирования нужны внешняя очередь задач и общее объектное хранилище;
- большие проекты требуют достаточно CPU, RAM, диска и времени работы контейнера; бесплатные тарифы хостингов могут быть недостаточны;
- browser upload не возобновляется после сетевого разрыва;
- анализ речи выполняется внутри запроса загрузки аудио и может занять заметное время на длинных дорожках; отдельная фоновая очередь анализа пока не реализована;
- Vercel обслуживает только frontend и не хранит загруженные медиа;
- переход `crossfade_safe` реализован как fade внутри границ каждого смыслового кадра, поэтому точная синхронизация не меняется.
